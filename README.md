# MiniC: транслятор підмножини C на Lex/YACC (PLY)

Конвеєр: **текст → Lexer → LALR(1)-Parser → AST → семантичний аналіз → (інтерпретація | генерація Python | візуалізація d3.js)**

## Встановлення і запуск
```bash
pip install ply
python3 main.py examples/demo.c --run                 # обчислення (інтерпретатор)
python3 main.py examples/demo.c --tokens              # токени
python3 main.py examples/expr.c --ast                 # AST текстом
python3 main.py examples/demo.c --py out.py           # генерація коду на Python
python3 main.py examples/demo.c --html ast.html       # візуалізація AST (відкрити у браузері)
python3 main.py examples/demo.c --debug               # parser.out: стани й таблиці LALR
python3 conflicts_demo.py                             # показ shift/reduce і reduce/reduce
```

## Мова
Типи `int`, `float`, `void`; глобальні й локальні змінні; функції та рекурсія; `if/else`, `while`, `for`
(у т.ч. `for (int i = 0; ...)`); `return`; вбудований `print(...)`; вирази з пріоритетами
`|| && == != < > <= >= + - * / %`, унарні `-` `!`; коментарі `//` і `/* */`.

## Теорія (для захисту)

**Що робить Lex / YACC.** Lex перетворює регулярні вирази на скінченний автомат і віддає потік токенів.
YACC за контекстно-вільною граматикою будує таблиці LALR(1) (ACTION і GOTO) і керує розбором знизу вгору
зі стеком станів та значень. Семантична дія `{ $$ = ... }` (у PLY: `p[0] = ...`) виконується при кожному reduce.

**LR-розбір.** Аналізатор читає токени зліва направо і будує *правосторонній вивід у зворотному порядку*.
Дії: **shift** (перенести токен у стек), **reduce** (замінити праву частину правила на лівий нетермінал),
**accept**, **error**. Стан = множина LR(0)-пунктів `A → α • β`, тобто «що вже розпізнано».

**LALR(1).** Беруться стани LR(0)-автомата, а до кожного пункту додається множина lookahead-символів.
Стани LR(1) із однаковим ядром зливаються (LALR). Таблиця стає такою ж малою, як SLR/LR(0), а перевірка
lookahead лишається. Мінус: злиття може створити reduce/reduce конфлікти, яких немає в канонічному LR(1).
LALR потужніший за SLR і слабший за canonical LR(1).

**Конфлікти і як їх розв'язує YACC.**
* **shift/reduce** (у стані можна і перенести, і звести). За замовчуванням YACC обирає **shift**.
  Пріоритети (`precedence`) і асоціативність (`left/right/nonassoc`) порівнюють пріоритет правила (за
  його останнім термінал-ом або `%prec`) з пріоритетом lookahead-токена: вищий пріоритет токена → shift,
  вищий правила → reduce, рівні → за асоціативністю (left → reduce, right → shift, nonassoc → помилка).
  У проєкті так розв'язано пріоритети операторів і *dangling else*: `ELSE` має вищий пріоритет за
  `%prec IFX`, тож `else` прив'язується до найближчого `if`.
* **reduce/reduce** (можна звести за двома правилами). YACC обирає правило, що **раніше в граматиці**;
  це майже завжди ознака помилки граматики, її краще переписати (див. `conflicts_demo.py`).
* Скільки конфліктів лишилось, видно в `parser.out`. У нашій граматиці їх **0** після застосування precedence.

**Відновлення після помилок.** `p_error` викликається, коли для (стан, токен) у таблиці немає дії.

## Питання по коду (підготовка)
* *Де будується AST?* У діях правил `parser.py`, кожне створює `Node`.
* *Чому `-` має `%prec UMINUS`?* Унарний мінус має вищий пріоритет, ніж бінарний, а токен у них один.
* *Чому assignment — statement, а не expression?* Спрощення граматики (менше конфліктів), `for` приймає `simple_stmt`.
* *Як реалізовано області видимості?* `semantic.py` — стек словників; `interp.py` — ланцюжок `Env`.
* *Як працює `return` в інтерпретаторі?* Через виняток `Return`, що розмотує стек виконання.
* *Чому `/` для int окремо?* У C ділення цілих усікається до нуля, у Python `//` округлює вниз; `_div` це виправляє.
* *Як `for` транслюється в Python?* `init; while cond: body; step`.
* *Обмеження:* немає масивів, указівників, структур; змінна, що перекриває глобальну, у Python-коді не підтримується.
